## 0. 先复盘 14:52 那次熔断 —— 熔断没错，是**阈值用错了地方**

```
14:52:03 ▶ 直接执行程序 411（加载 + 运行一次下发）
14:52:03 程序 411 已加载（0.61s）
14:52:03 程序熔断已武装：J4 ≤ 10° / 其他 ≤ 5°
14:52:07 熔断触发（其他轴越界 J2 5.63° > 5°）→ 下发 0x1005 停止
```

**发生了什么**：411 跑起来后，**J2 在 4 秒内走了 5.63°**，超过"其他轴限 5°" → 熔断掐停。

**为什么会这样**：那 5° 是**给单轴点动用的保守值**（点动时"其他轴"理论上不该动，5° 是防跑偏的）。
可**作业程序本来就该让轴大幅运动**（J2 走 30° 很正常）—— 拿点动的尺子量作业程序，必然误杀。

**所以你说的"越界检测只能在测试运行时"是对的。** 熔断是**测试辅助**，不该出现在生产执行路径上。

## 1. 改造一：**测试跑** / **执行** 两档彻底分离

| | **测试跑**（Test） | **执行**（Run） |
|---|---|---|
| 用途 | 验证程序、第一次跑新程序、试点位 | 生产 / 正常作业 |
| 速度 | **强制 5%**（忽略界面设定） | 界面设定值 |
| **定时** | **开** —— 跑 N 秒自动停（默认 3s，界面可选 2/3/5/10/30/60，也可手输） | 不适用（跑完整程序） |
| **越界熔断** | **开** —— 任一关节位移 > 上限即停（默认 45°）+ 300s 兜底 | **关** |
| 二次确认 | 不需要（它本身就是"安全的低速限时试跑"） | 不需要（一键下发，按你的要求） |
| 跑完 | **不**自动恢复点动（停在现场便于检查） | 按 ☑ 开关自动恢复点动 |
| 按钮 | 【▶ 测 试 跑】(warn) | 【▶ 执  行】(ok) |

**"定时"是 2026-09-23 新增的**（你的原话："测试的可以跑 3 秒、2 秒这种可以定时间的去跑"）——
有了定时，测试跑就有了**确定的结束条件**，不再依赖"程序自己跑完"或"越界"。

**两档都保留的硬保护**（这些不是"越界检测"，是安全底线）：

- **报警 / 急停** → 立刻 `0x1005` 并撤触发
- **通信中断** → 自动重连 + 明确提示（不静默）
- **伺服掉电** → 拒绝动作 + 提示
- **急停（Esc）** → 任何时候可用，且**绝不自动恢复任何东西**

## 2. 改造二：**程序清单**（不再猜程序号/程序名，也不再靠扫描覆盖下拉）

### 为什么改成"用户自己维护的清单"

现场扫描结论（2026-09-21 / 09-23 两次一致）：

| 区间 | 存在的程序号 |
|---|---|
| 1~300 | **无**（**没有 200**） |
| 301~600 | ✅ **410（0.51s）、411（0.55s）** |
| 601~999 | **无** |

⇒ 面板原来硬编码的"点动服务程序 = 200"**根本不存在**，所以每次【一键就绪】都白报一次 5005。
⇒ 而且 **Modbus 只认数字号（40104），控制器不会把程序名吐出来**；程序文件却可能叫
`PICK_A.XPL` 这种**英文名** —— 名字只有示教器上有。

所以（你的原话："不要猜程序名称也要可能是英文…用户可以自己添加文件…记得保存文件，可以增删什么的"）：

**清单由用户维护，落盘到 `programs.json`：**

```json
{
  "version": 1,
  "jog": 200,
  "list": [
    {"no": 200, "name": "JOGSVC",  "note": "点动服务程序"},
    {"no": 410, "name": "PICK_A",  "note": "上料"},
    {"no": 411, "name": "WELD_B",  "note": ""}
  ]
}
```

- **号**（`no`）= 唯一会下发给机器人的东西（写 `40104`）
- **名字 / 备注** = 纯本地备注，方便你自己认，**不下发**
- 支持 **添加 / 改名 / 删除**；每次改动**原子落盘**（临时文件 + `os.replace`）
- `jog` = 哪一条是"**点动服务程序**"（0 = 未设置）；由界面上的【设为点动服务】声明
- 文件损坏 → 改名留档为 `.bad`，**绝不静默覆盖**你的手写清单
- 程序号存在下拉的 **item data** 里，不是从文本抠数字 → 名字里带数字（`PICK_A2`）也不会解析错

### 扫描（可选，仍然有用）

⑤ 卡【扫描】保留：写 `40104` → `0x1011` 加载 → **正反双判据**（报警先到=不存在，加载位先到=存在）。
**只加载、绝不运行**。扫到的程序号**自动并入清单**（只加没有的，**不动**你已写的名字）。

判据的实测依据（`tools/probe_load.py` 时间线）：

| 程序 | `40001.Bit11` 加载位 | 报警 | 耗时 |
|---|---|---|---|
| **411**（存在） | `0 → 1` | 无 | **0.50s** |
| **123 / 3**（不存在） | 从未置位 | **5005** | **0.08s** |
| `40006` 当前程序号 | 加载成功/失败都**不变** | — | 当不了判据 |

> ⚠ 历史 bug：旧版等待窗口 **0.5s**，而真实加载要 **0.50~0.61s** —— 卡在临界点上，
> 411 明明存在却被报成"（无）"，而且当时扫的是 `1~260`，411 根本不在区间内。
> 现已改为 ≥1.2s 窗口 + 双判据 + 提前退出 + 状态机（扫描期间 UI/快照/急停全程可用）。

## 3. 改造三：点动区 → **6 个点坐标** + "当前在动哪个点"

按你的要求："关键点动删除掉，只需要 6 个点坐标和哪个点在动那种"。

**删除**：J1~J6 × 8 按钮的栅格（48 个按钮）+ 6 条位移色条。

**改成**：

```
④ 关节        当前在动：J4          步长 [1° ▼]   其他轴限 [1.5°]
  J1   +73.340°   [ − ]  [ + ]   ● 在动   Δ+0.00
  J2   −49.490°   [ − ]  [ + ]            Δ+0.00
  … 共 6 行
```

- **6 个坐标**实时显示；哪个轴在动 → 坐标变蓝 + 显示「**● 在动**」+ 顶部汇总「当前在动：J4」
- 「Δ」= 自【设基线】以来的位移

> 关于"6 个点"这个词：现场口径里的"点"= **关节轴**，所以这里就是 6 个轴坐标 + 在动指示。
> 如果哪天你指的是"6 个示教点位 P1~P6"（记录姿态→去这里），那是**另一个功能**，说一声我加。

## 4. 改造四：示教器 J1~J6 的 ± 控制命令（12 个）

### 结论：**原生那 12 个命令拿不到，所以不再去获取。**

你的原话："获取不到就不要获取"。已确认不可得，理由：

| 路子 | 结果 |
|---|---|
| 抓示教器↔控制器的报文 | ❌ 示教器在 **ETH3A**、我们在 **ETH3B**，是控制器内部链路 —— PC 侧抓不到 |
| Modbus 里找关节指令 | ❌ 已穷举：`40101` 指令位只到 Bit13，**没有任何关节级/点动指令** |
| 8000 端口（疑似墨斗 IDE 私有协议） | ⚠️ 存在但**无任何文档** —— 对运动控制器盲试有真实风险，不做 |

### 交付的等价物

**6 轴 × −/+ = 12 个按钮**（步长 0.1 / 0.5 / 1 / 5 / 10° 可换），走**已在真机验证过的通道**：

```
写 40139~44（绝对目标角 ×100）→ 置 40135.Bit0 触发
→ 常驻程序 WAIT 放行 → MJOINT → 回执 40035.Bit0 → 撤触发、基线归零
```

功能与示教器那 12 个键一致，且不依赖任何未公开协议。

## 6. 上一轮 3 个待拍板项的结论（已由现场反馈确定）
