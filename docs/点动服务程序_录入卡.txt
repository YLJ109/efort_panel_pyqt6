【要插入的 5 条指令】   菜单路径 → 参数
----------------------------------------------------------------
① 循环/Loop        → WHILE     条件保持默认 true
                                （ENDWHILE 会自动加，别自己敲）
② 基本/Basic       → 赋值 /:=  变量: fidbus.mtcp_wo_b[0]
                               表达式: false
③ 基本/Basic       → WAIT      条件【编辑】: fidbus.mtcp_ro_b[0]
④ 运动/Movement    → MJOINT    速度:   v100perc      ← 下拉选
                               圆滑:   fine
                               工具:   tool0
                               坐标系: wobj0
                               目标点: 类型选【固定 POINTJ】，6 个表达式分别填
                                   fidbus.mtcp_ro_i[0]/100
                                   fidbus.mtcp_ro_i[1]/100
                                   fidbus.mtcp_ro_i[2]/100
                                   fidbus.mtcp_ro_i[3]/100
                                   fidbus.mtcp_ro_i[4]/100
                                   fidbus.mtcp_ro_i[5]/100
⑤ 基本/Basic       → 赋值 /:=  变量: fidbus.mtcp_wo_b[0]
                               表达式: true
⑥ 基本/Basic       → WAIT      条件【编辑】: NOT fidbus.mtcp_ro_b[0]
                               （★ 等上位机撤触发 —— 防止同一发被重复执行）

★★ 最容易错的就是 ③ 那条：WAIT 必须等【读区】fidbus.mtcp_ro_b[0]。
   若写成【写区】fidbus.mtcp_wo_b[0]，程序第一句刚把它置成 false → 永远等不到，
   程序会**卡死在 WAIT**。现象：上位机「运行」位常亮、40035 完成位恒 0、机器人一动不动。

最后：任务栏【保存】   ← 不保存的话，修改是临时的（官方原文）


【完整代码（RPL 文本，对照用 —— 别用记事本手打成 .XPL，会报 4902）】
----------------------------------------------------------------
先到【变量】页声明 6 个 LREAL 程序变量（名字随意，用小写更保险）：

    名称     类型
    j1       LREAL
    j2       LREAL
    j3       LREAL
    j4       LREAL
    j5       LREAL
    j6       LREAL

主程序体（Main）：

    WHILE true DO
        fidbus.mtcp_wo_b[0] := false;
        WAIT(fidbus.mtcp_ro_b[0]);
        j1 := fidbus.mtcp_ro_i[0]/100.0;
        j2 := fidbus.mtcp_ro_i[1]/100.0;
        j3 := fidbus.mtcp_ro_i[2]/100.0;
        j4 := fidbus.mtcp_ro_i[3]/100.0;
        j5 := fidbus.mtcp_ro_i[4]/100.0;
        j6 := fidbus.mtcp_ro_i[5]/100.0;
        MJOINT(POINTJ(j1,j2,j3,j4,j5,j6), v100perc, fine, tool0);
        fidbus.mtcp_wo_b[0] := true;
        WAIT(NOT fidbus.mtcp_ro_b[0]);
    END_WHILE;

逐行 | 作用
---------------------------------------------------------------
WHILE true DO           死循环 —— 让程序常驻，不退出
mtcp_wo_b[0] := false   清回执（告诉上位机"我准备好接新指令"）
WAIT(mtcp_ro_b[0])      ★ 等【读区】触发（= 40135.Bit0）。平时就停在这一行
j1..j6 := ro_i[i]/100.0 把 40139~44 的 6 个整数角还原成度（通道里是 ×100）
MJOINT(POINTJ(...))     运动到 6 个绝对关节角
mtcp_wo_b[0] := true    置回执（= 40035.Bit0），告诉上位机"到位了"
WAIT(NOT ro_b[0])       ★ 等上位机把触发位撤掉 → 同一发不会被执行两遍
END_WHILE               回到开头，等下一次点动


【每行在干什么】
----------------------------------------------------------------
WHILE true              死循环 —— 让程序永远挂着不退出（常驻）
mtcp_wo_b[0] := false   清回执：告诉上位机"我准备好了，可以发新指令"
WAIT(mtcp_ro_b[0])      挂起等触发 —— 上位机置 40135.Bit0 才往下走
                        （★ 程序平时就停在这一行，所以不会自己乱动）
MJOINT(...)             运动到通道里给的 6 个绝对角
mtcp_wo_b[0] := true    置回执：告诉上位机"到位了"（40035.Bit0）
END_WHILE               回到开头，等下一次点动


【变量对应关系（官方手册 15.4.5）】
----------------------------------------------------------------
上位机 → 机器人   mtcp_ro_b[0]    = 40135 Bit0        点动触发（电平）
                  mtcp_ro_i[0..5] = 40139~40144       J1~J6 目标绝对角 ×100
机器人 → 上位机   mtcp_wo_b[0]    = 40035 Bit0        完成回执（1 = 已到位）
速度 = v100perc × 上位机倍率（40103，即面板上的「速度 %」）

【点动速度在哪调】（2026-09-23 实机实测）
  就在面板 ④ 卡右上角的「速度 %」—— 它写的 40103 同时就是点动速度闸门：
      40103 = 5%   → 约 1.3°/秒   （慢慢挪，适合对点）
      40103 = 100% → 约 60~90°/秒 （想要"转 1 秒"就设 60~90°）
  程序里的 v50perc 不锁死速度，别去改程序。

【"完成位秒回、但机器一点没动"】（2026-09-23 实测踩到）
  特征：触发后 0.1 秒内就收到完成位，可角度一动不动。
  原因：写 40139~44 后**立刻**置触发位，控制器还没把读区同步进程序变量空间，
        MJOINT 读到的是上一轮的旧目标角（= 当前角）→ 不动，但照常回执。
  已修：程序回读校验 + 静置 0.15 秒后才触发（tools/jog_axis.py 与 app/worker.py）。
  你要是自己写脚本，务必照做，别"写完就触发"。
