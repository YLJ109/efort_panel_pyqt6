# 埃夫特 EFORT 机器人 Modbus TCP 远程控制手册

> **版本** v1.0 · 2026-09-21 · 基于真机（ER 系列 / 控制器 RP-2）逐项实验验证
> **验证状态**：读、写、伺服上电、程序加载、程序运行、安全熔断——**全链路真机实证**（见附录 A 证据链）
> **适用**：通过 PC（上位机）经 Modbus TCP 远程监视与控制埃夫特工业机器人

---

## 0. 文档定位

| 你想做的事 | 直接跳到 |
|---|---|
| 第一次把 PC 连上机器人 | §2 网络层 + §7.1 |
| 只想看机器人状态（零风险） | §3.2 寄存器 + §6 `_probe_efort_watch.py` |
| 想让机器人上伺服（通电不动作） | §4.2 + §6 `_probe_efort_servo_pulse.py` |
| 想让机器人真的动起来 | §4.3 + §6 `_probe_efort_run.py` |
| 出问题了 | §8 陷阱清单 + §9 FAQ |

**能力边界（必读）**：Modbus TCP 是**程序级**接口——**没有"把某关节转到某角度"的寄存器**。
关节运动只能由机器人程序定义，Modbus 负责「上伺服 → 指定程序号 → 加载 → 触发运行 → 停止」。

## 1. 系统总览

### 1.1 架构

```
┌─────────────────────┐       Modbus TCP (FC3 读 / FC6 写)        ┌──────────────────┐
│   PC / 上位机        │ ────────────── 端口 502 ────────────────▶ │  控制器 RP-2      │
│  192.168.1.10/24    │                                            │  192.168.1.12    │
│  (ETH3B 对接口)      │ ◀────────── 40001~ 状态推送(轮询) ─────── │  (Modbus 从站)    │
└─────────────────────┘                                            └────────┬─────────┘
                                                                            │ ETH3A
                                                                       ┌────▼─────────┐
                                                                       │ 示教器         │
                                                                       │ 192.168.1.13  │
                                                                       └───────────────┘
```

机器人是 **Modbus TCP 从站（服务器）**，PC 是主站（客户端）。PC 不发命令时机器人照常运行，互不干扰。

### 1.2 控制权限三级模型

| 级别 | 内容 | 风险 | 本工具集对应 |
|---|---|---|---|
| **L1 只读** | 状态位 / 报警 / 程序号 / 关节角 | 零 | `_probe_efort_modbus.py`、`_probe_efort_watch.py` |
| **L2 上电** | 伺服使能（驱动器通电、保持位置、不动） | 低（可逆） | `_probe_efort_servo.py`、`_probe_efort_servo_pulse.py` |
| **L3 运动** | 加载程序 + 触发运行 + 停止 | **高（物理动作）** | `_probe_efort_run.py`（带熔断） |

每升一级都应有明确授权，不要一步到位。

### 1.3 验证状态总表（本机实测）

| 能力 | 状态 | 证据摘要 |
|---|---|---|
| TCP 连通 502 | ✅ | 端口开放，从站号 **1** 应答（0 无应答） |
| 读状态/关节角 | ✅ | 重叠地址对照 **10/10 一致**；关节角 CDAB 解码全部在 ±180° 内 |
| 写通道 | ✅ | 用户变量 40301 写哨兵 0x5A5A → 读回一致 → 还原 |
| 伺服上电（PC 控制） | ✅ | 写 0x1001 后 ~0.55s `伺服`(Bit3)=1 并保持 |
| 程序加载（PC 控制） | ✅ | 写 0x1011 后 `程序加载`(Bit11)=1 |
| 程序运行（PC 控制） | ✅ | 写 0x1013 后机械臂真实运动（实测程序 123 为多轴轨迹） |
| 安全停止（PC 控制） | ✅ | 越界熔断写 0x1005，运动立刻停止，无报警 |

## 2. 网络层

### 2.1 控制器网络参数（埃夫特默认）

| 项 | 值 |
|---|---|
| 控制器 IP | `192.168.1.12` / 255.255.255.0 |
| 示教器 IP | `192.168.1.13` |
| 对外通信口 | **ETH3B**（**别插 ETH3A**，那是示教器口） |
| Modbus 端口 | **502（固定，不可改）** |
| 示教器解锁密码 | `1975`（改 IP 用）；示教器登录 `999999` |

### 2.2 PC 侧配置

PC 需要一个 `192.168.1.x` 的地址（控制器不跑 DHCP）。**追加**而非替换现有地址（可逆）：

```powershell
# 管理员 PowerShell —— 给网卡追加 192.168.1.10/24
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.1.10 -PrefixLength 24 -SkipAsSource $true
```

或用本项目自提权脚本（纯 ASCII 启动器 + UTF-8 BOM 的 ps1）：

```
run_as_admin_setup_robot_net.bat        # 自动提权并执行 setup_robot_net.ps1
setup_robot_net.ps1                     # 多厂商版：默认埃夫特 192.168.1.10 → 192.168.1.12
                                        # 华沿用：-PcIp 192.168.0.10 -RobotIp 192.168.0.100
```

### 2.3 连通性诊断（按层排查，勿跳步）

```
① 网卡层   Get-NetAdapter  → Status=Up、Media=Connected？（网线物理通）
② IP 层    本机是否有 192.168.1.x 地址？（没有 → 无路由，所有端口必然超时）
           ⚠ 网卡停在 169.254.x.x（APIPA）= 线通但没 IP，需手动配置
③ ARP 层   arp -a | findstr 192.168.1   → 有单播条目 = 对端应答过
           只有广播/组播条目 = 对端从未应答（不能断定在线，但基本不通）
④ 驱动计数 Get-NetAdapterStatistics（防火墙无关，最可信）
           ⚠ 该命令没有 -InterfaceIndex 参数 —— 先按 index 取网卡名再按 Name 过滤
           ⚠ 累计值可能是历史遗留，判"当前通不通"必须看**增量**（如 20~45s 窗口 RX 增量）
⑤ 端口层   TCP 探测 502（首探给长超时或先 ping 预热——刚加完 IP 第一个探测常因
           ARP 未解析而误报"不通"）
⑥ 协议层   Modbus FC3 读 40001（从站号 1）
```

**反面教材**：被动 UDP 侦听不可信——Windows 防火墙拦未登记程序的入站，自检走本机回环通过 ≠ 能收外部包。

## 3. Modbus 协议层（本机实测）

### 3.1 基本参数

| 项 | 值 | 备注 |
|---|---|---|
| 传输 | Modbus TCP | MBAP 头 7 字节 |
| 从站号（Unit ID） | **1** | 0 无应答 |
| 端口 | 502 | 固定 |
| 读取 | FC3（Read Holding Registers） | |
| 写入 | FC6（Write Single Register） | 实测可用 |

### 3.2 寄存器映射（4xxxx 保持寄存器，0 基地址 = 4xxxx − 1）

**→ 机器人状态（PC 只读）**

| 地址 | 0 基 | 类型 | 含义 |
|---|---|---|---|
| 40001 | 0 | BOOL 位域 | Bit0 手动 / **Bit1 自动** / Bit2 远程 / **Bit3 伺服** / Bit4 报警 / Bit5 急停 / **Bit6 程序运行** / Bit7-10 安全位置 1-4 / **Bit11 程序加载** / Bit12 伺服准备 / Bit13 程序预约激活 / Bit14 程序复位 |
| 40003 | 2 | INT | 运行速度（全局，%） |
| 40004 / 40005 | 3 / 4 | INT | 报警代码 1 / 2 |
| 40006 | 5 | INT | 当前程序号 |
| **40011~40022** | 10~21 | FLOAT | **J1~J6 关节角（度）**，每轴 2 寄存器 |
| 40023~40030 | 22~29 | FLOAT | J7~J10（附加轴） |
| 40035+ / 40135+ | 34+ / 134+ | — | 用户变量区（机器人输出，只读） |

**→ PC 命令（PC 写，机器人执行）**

| 地址 | 0 基 | 类型 | 含义 |
|---|---|---|---|
| **40101** | 100 | BOOL 位域 | **Bit0 上/下伺服 · Bit1 运行 · Bit2 停止 · Bit3 清除报警 · Bit4 加载程序 · Bit12 伺服使能 · Bit13 取消伺服使能** |
| 40103 | 102 | INT | 设置机器人速度（%） |
| 40104 | 103 | INT | 目标程序号 |
| 40301+ / 40401+ | 300+ / 400+ | — | 用户变量读写信箱（写测试已验证） |

**⚠ FLOAT 字序是 CDAB（字交换）**。同一段寄存器按 ABCD 解会得到 `2.1e11 / 5.3e12` 这类荒谬值，
按 CDAB 解全部落在 ±180° 内。判真伪就看物理范围。

### 3.3 本控制器的"脾气"（逐条实测，绕不过去）

1. **逐地址单读只有 4 个合法窗口**，每个 10 个寄存器：
   `0~9`（40001~40010）、`34~43`（40035~40044）、`100~109`（40101~40110）、`134~143`（40135~40144）。
   其余地址单读一律**异常码 2**。
2. **J1~J6（40011~40022）单读必失败** → 只能**从地址 0 起做大块读**"夹带"出来（读 ≥22 个即可，**用 24 或 32 最稳**）。
3. **读取数量白名单**：`1..8, 10, 12, 16, 20, 24, 32, 48, 64`。
   **`23` 确定性失败**（异常码 2），`100/125` 也失败。⚠ 通用只读脚本若一次读 23 个必挂，要读 24。
4. **长读按「绝对地址」返回**（不是块内回绕）。验证手法：挑一段单读合法的地址与长读重叠区逐一比对（本机 10/10 一致）——**凡用大块读取数，先做这个重叠校验再采信**。
5. **命令位是"同沿"语义**（详见 §4.2，最重要的坑）。

## 4. 控制时序

### 4.1 从零到运动的完整状态机

```
[网络通] ──▶ [只读验证] ──▶ Auto模式? ──▶ 伺服上电 ──▶ 写程序号+加载 ──▶ 触发运行 ──▶ [运动中]
                │                │            │             │                │          │
                │                └ T1/T2 则   │             │                │          ├─ 监视关节角
                │                  拒绝      │             │                │          │  （熔断）
                ▼                           ▼             ▼                ▼          ▼
            重叠校验数据                 0x1001        0x1011           0x1013      0x1005
                                          同沿写         加载位=1          运行        停止
```

**前置模式：必须 Auto**（`40001` Bit1=1）。官方资料明确：**T1/T2（手动）模式下外部设备的控制信号一律无效**，
只有 Auto 模式允许外部做"程序选择 / 伺服上电 / 运行指令"。

**`远程`(Bit2) 不是闸门**：本机实测伺服上电、程序加载、程序运行**全程 `远程=0`** 均成功。
不要在这位上浪费时间（本项目曾误判过两次，见附录 A）。

### 4.2 伺服上电的正确姿势（本节是血泪精华）

**命令字必须从 0 一条写入，两个位同沿：**

```
写 40101 = 0x1001        # Bit0 上伺服 + Bit12 伺服使能，同一条写入
```

| 写法 | 结果 | 原因 |
|---|---|---|
| 一条写 `0x1001`（从 0x0000） | ✅ ~0.55s 后 `伺服`=1 并保持 | 两个位**同时产生上升沿**，命令被识别 |
| 先写 `0x1000` 再写 `0x1001` | ❌ 伺服不上 | 第二次写时 Bit12 **没有新沿**，命令不被识别 |

**时序坑：伺服要 ~0.55s 才置位。** 写完 0.5s 读一次会**恰好错过**、误判失败；
必须以 ≤100ms 高频采样（`_probe_efort_servo_pulse.py` 的存在意义）。

**误判的连锁反应（真实事故案例）**：写 → 0.5s 读太早 → 误判"没生效" → 跑 `--disable` 掐掉正在吸合的伺服 →
现场听到"哐"一声（**抱闸落下的声音，正常现象，不是急停**）。教训：**下电前先确认状态真没起来**。

**取消伺服（下电）**：写 `0x2000`（Bit13 取消伺服使能）→ 再写 `0x0000` 清空。

### 4.3 程序加载与运行（命令字组合表）

**铁律：每条命令字都必须保留伺服位 `0x1001`**（写整寄存器会覆盖全部位，漏掉伺服位 = 伺服掉电抱闸）。

| 动作 | 命令字 | 组成 | 验证 |
|---|---|---|---|
| （保持基字） | `0x1001` | Bit0 + Bit12 | 伺服保持通电 |
| **加载程序** | `0x1011` | `0x1001 \| Bit4` | `程序加载`(Bit11) → 1 |
| **运行** | `0x1013` | `0x1001 \| Bit4 \| Bit1` | `程序运行`(Bit6) → 1，机械臂运动 |
| **停止** | `0x1005` | `0x1001 \| Bit2` | 运动立刻停止 |
| 下电 | `0x2000 → 0x0000` | Bit13 → 清零 | 伺服=0，抱闸落下 |

**标准运动序列：**

```python
write 40103 = 5            # 速度兜底（5%）——即使示教器已设，也再写一次
write 40104 = <程序号>       # 目标程序
write 40101 = 0x1011        # 加载（等 Bit11=1，~2s 内）
write 40101 = 0x1013        # 运行
# ... 150ms 高频监视关节角 ...
write 40101 = 0x1005        # （需要时）停止
write 40101 = 0x1001        # 收尾恢复：只保持伺服
```

**再次强调协议边界**：Modbus **没有**"把 J6 移到某角度"的指令。
想让某个关节动，唯一路径是**先在示教器上写一个只动该关节的机器人程序**，再由 PC 触发。

### 4.4 关节角读取（数据可信度）

从地址 0 一次读 32 个寄存器，取 `regs[10..21]` 按 CDAB 解 J1~J6：

```python
def f32_cdab(hi_reg, lo_reg):
    raw = (lo_reg << 16) | hi_reg          # 字交换（CDAB）
    return struct.unpack(">f", raw.to_bytes(4, "big"))[0]
```

## 5. 安全规程（红线，不可协商）

### 5.1 运动前"四件套"确认（逐项口头确认，缺一不跑）

1. **作业区清空**：臂体扫掠范围内无人、无遮挡；
2. **急停可达**：操作者手边有急停按钮，随时拍得着；
3. **速度最低**：示教器速度已降到最低档（如 5%），PC 侧再写 `40103=5` 双保险；
4. **程序已知**：**程序内容经过当面核实**——⚠ 实测教训：口述"这程序只动 J6"不可信，
   程序 123 实际是六轴联动轨迹，靠熔断才拦住（附录 A.6）。

### 5.2 实时熔断（`_probe_efort_run.py` 内置）

| 熔断条件 | 阈值 | 依据 |
|---|---|---|
| 非目标轴位移 | **> 2°** | 授权"只动 J6"时其他轴不该动 |
| 目标轴位移 | > 20°（授权 10° 的 2 倍） | 留余量防程序跑飞 |
| 报警 / 急停位 | 任一出现 | 立即停 |
| 运行超时 | 60 s | 程序不该跑这么久 |

触发即写 `0x1005` 停止 → 0.5s 后恢复 `0x1001`（保持伺服）→ 报告中断位姿。

### 5.3 绝对禁止

- ❌ **盲跑未知程序**（内容没核实就写运行位）；
- ❌ 分步写伺服位（先 Bit12 后 Bit0）——命令不被识别还容易误判；
- ❌ 写命令字时**丢掉伺服位**——运动中伺服掉电 = 抱闸急停，伤机械；
- ❌ 一次读 23 个寄存器（必失败）；
- ❌ 用 ABCD 字序解关节角（必得荒谬值）；
- ❌ T1/T2 模式下发外部命令（一律无效，白忙）；
- ❌ 首次端口探测失败就断定"不通"（先 ping 预热再探）。

## 6. 工具脚本手册

全部位于 `C:\ros2_ws\_devtmp_archive\robot_probe\`，**仅用 Python 标准库**（socket + struct，无第三方依赖）。
运行环境：Python ≥ 3.10（本项目用 venv `fluent6`）。

### 6.1 `_probe_efort_modbus.py` — 全量只读快照（L1）

```
用法:  python _probe_efort_modbus.py [IP，默认 192.168.1.12]
安全:  只有 FC3 读，结构上不可能让机器人动作
输出:  40001 全部状态位、40003~40006、J1~J6（CDAB/ABCD 双解对照）、
       40101~40104 指令位、用户变量区
```

### 6.2 `_probe_efort_watch.py` — 实时监视（L1）

```
用法:  python _probe_efort_watch.py <IP> <时长秒> <间隔秒>
       例: python _probe_efort_watch.py 192.168.1.12 90 0.5
安全:  只有 FC3 读
输出:  2.5Hz 轮询 8 个状态位 + J1~J6，变化高亮；结束给各轴活动幅度汇总
用途:  ① 验证读链路（示教器手动点动 J6，看角度是否跟随）
       ② 运动后确认关节静止  ③ 观察模式位切换
实现:  固定从地址 0 读 32 个（J 区不能单读、23 个必失败）
```

### 6.3 `_probe_efort_safewrite.py` — 写通道验证（L1，安全写）

```
用法:  python _probe_efort_safewrite.py <IP> test [addr]
       例: python _probe_efort_safewrite.py 192.168.1.12 test 300
安全:  硬闸门——地址 < 300 一律拒绝写入（40101/40103/40104 结构上不可能被写）
流程:  读原值 → 写哨兵 0x5A5A → 读回校验 → 还原原值（不留痕迹）
用途:  证明"能写"而不让机器人产生任何动作
```

### 6.4 `_probe_efort_servo.py` — 受控伺服上/下电（L2）

```
用法:  python _probe_efort_servo.py <IP> [--enable | --disable]
       不带参数 = dry-run（只打印写前状态，不写）
安全:  只写 40101 伺服位；上电本身不产生运动；可逆（--disable 或急停）
流程:  写 0x1000(Bit12) → 不生效则补 0x1001 —— ⚠ 此分步写法在真机上不可靠，
       推荐用 6.5 的脉冲脚本
```

### 6.5 `_probe_efort_servo_pulse.py` — 伺服上电（推荐，L2）

```
用法:  python _probe_efort_servo_pulse.py <IP>
安全:  只写 40101 = 0x1001（同沿），不写运行/程序位 → 只通电不动作
流程:  写前读状态/关节角/报警码 → 写 0x1001 → 100ms 高频轮询 5s 抓瞬时置位
       → （未置位则清零脉冲重试一次）→ 读后对照
输出:  状态跳变时间线、伺服是否保持、关节最大变化（应为 ~0）、报警码
```

### 6.6 `_probe_efort_run.py` — 加载并运行程序（L3，带熔断）

```
用法:  python _probe_efort_run.py <IP> <程序号> [速度，默认5]
       例: python _probe_efort_run.py 192.168.1.12 130 5
前置:  伺服=1、报警=0、急停=0，否则拒绝运行
流程:  40103=速度 → 40104=程序号 → 0x1011 加载(等Bit11) → 0x1013 运行
       → 150ms 监视（§5.2 熔断表）→ 结束恢复 0x1001
输出:  基线/结束关节角、各轴最大位移、J6 净位移、是否熔断
```

## 7. 标准作业流程（SOP）

### 7.1 首次部署（每台新机器一次）

```powershell
# 1. 网线插控制器 ETH3B，管理员跑：
run_as_admin_setup_robot_net.bat          # 追加 192.168.1.10/24 并探测

# 2. 只读验证（应看到：自动=1，六轴角度合理）
python _probe_efort_modbus.py 192.168.1.12

# 3. 写通道验证（哨兵写-读回-还原，不动机器人）
python _probe_efort_safewrite.py 192.168.1.12 test 300
```

### 7.2 日常控制（每次）

```powershell
# ── L1 状态确认 ──
python _probe_efort_modbus.py 192.168.1.12
#   检查：自动=1（不是则先去示教器切 Auto）、报警=0、急停=0

# ── L2 伺服上电（通电不动作）──
python _probe_efort_servo_pulse.py 192.168.1.12
#   预期：~0.55s 后 伺服=1 并保持；关节最大变化 ≈ 0

# ── 四件套确认（§5.1）──
#   区域清空 / 急停可达 / 速度最低 / 程序内容已当面核实（在示教器上打开看过！）

# ── L3 运行程序（带熔断）──
python _probe_efort_run.py 192.168.1.12 <程序号> 5
#   预期：加载位=1 → 机械臂按程序运动 → 程序结束自动恢复
#   异常：任何越界立即被熔断停止并报告中断位姿
```

### 7.3 收尾

```powershell
python _probe_efort_servo.py 192.168.1.12 --disable    # 下伺服（抱闸"哐"一声是正常的）
```

## 8. 已知陷阱清单（血泪史，按踩中概率排序）

| # | 陷阱 | 症状 | 对策 |
|---|---|---|---|
| 1 | **命令位分步写** | 伺服怎么都不上 | 从 0 一条写 `0x1001`（同沿） |
| 2 | **写后 0.5s 才读状态** | 误判"没生效"（伺服 ~0.55s 才置位） | ≤100ms 高频采样 |
| 3 | **一次读 23 个寄存器** | 异常码 2，确定性失败 | 读 24 或 32 |
| 4 | **J1~J6 单地址读** | 异常码 2 | 从地址 0 大块读夹带 |
| 5 | **ABCD 字序解浮点** | 角度出现 2.1e11 之类 | 用 CDAB |
| 6 | **口述程序内容不可信** | "只动 J6"实际六轴齐动 | 必带熔断监视（§5.2） |
| 7 | **写命令字漏伺服位** | 运动中伺服掉电抱闸 | 每条命令字都含 0x1001 |
| 8 | **`远程=0` 当闸门** | 反复在示教器找"远程开关"白忙 | 实测不影响上电/加载/运行，别管它 |
| 9 | **T1/T2 下发命令** | 全部无效 | 必须 Auto 模式 |
| 10 | **首探端口误报不通** | 刚配完 IP 探 502 超时 | 先 ping 预热或给长超时 |
| 11 | **累计网卡计数判状态** | 拿历史流量误判"在线" | 看增量（20~45s 窗口） |
| 12 | **中文 GBK/UTF-8 乱码** | PS 输出匹配网卡名失败 | 命令开头加 `[Console]::OutputEncoding=[Text.Encoding]::UTF8;` |

## 9. 故障排查 FAQ

**Q1：TCP 连上了但 Modbus 无应答？**
从站号用 **1**（0 无应答）；确认服务启用（埃夫特部分固件 Modbus 服务默认关闭，藏较深，
且有些设置**需重启控制器生效**——改完设置重启一次最稳）。

**Q2：读某些地址返回异常码 2？**
见 §3.3：单读窗口只有 4 个（0~9 / 34~43 / 100~109 / 134~143），J 区必须大块读，数量避开 23。

**Q3：写了 40101 伺服就是不上？**
按序排查：① 模式是 Auto？② 命令是一条写 `0x1001` 吗（不是分步）？③ 等够 0.6s 再判？
④ 有报警（40004/40005）先清（写 40101 Bit3）？⑤ 采样频率够高吗（≥100ms）？

**Q4：程序触发了但机器人不动？**
① 伺服=1 吗（Bit3）？② 40104 写对程序号了吗？③ 加载位（Bit11）置位了吗？
④ 程序本身是否需要外部条件（如输入信号、安全门）？

**Q5：运动中发现轨迹不对，怎么紧急停？**
写 `40101 = 0x1005`（保持伺服的停止）；或直接拍现场急停（最硬）。`_probe_efort_run.py` 的熔断会自动做前者。

**Q6：听到"哐"一声巨响？**
大概率是**抱闸落下**（伺服掉电的正常声音），不是撞机。核对：关节角是否静止、报警码是否为 0。

### A. 验证证据链（2026-09-21 真机实测）

| # | 实验 | 结果 |
|---|---|---|
| A.1 | 端口扫描 | 502 / 8000 / 80 开放；从站号 1 应答 |
| A.2 | 长读绝对地址验证 | 单读 34~43 与长读重叠区 **10/10 一致** |
| A.3 | CDAB 字序实证 | ABCD 解出 −0.0/2.1e11/5.3e12（荒谬）；CDAB 全在 ±180° |
| A.4 | 读数量白名单 | 1..8,10,12,16,20,24,32,48,64 成功；**23 三次全败**；100/125 败 |
| A.5 | 写通道验证 | 40301 写 0x5A5A → 读回 23130 一致 → 还原 0 |
| A.6 | **伺服上电** | 一条写 0x1001 → **t≈0.55s 伺服(Bit3)=1 保持 5s+**，关节变化 0.0009° |
| A.7 | **程序加载+运行** | 0x1011 → Bit11=1；0x1013 → **机械臂真实运动**（程序 123 实为多轴轨迹：J1 1.09°/J2 2.11°/J3 0.91°/J4 2.23°/J5 0.55°，J6 仅 0.37°） |
| A.8 | **熔断停止** | 其他轴 >2° 触发 → 写 0x1005 → **运动立即停止**，无报警，伺服保持 |
| A.9 | 远程位全程为 0 | 伺服/加载/运行均成功——证明 Bit2 非闸门 |

又因采样太慢误杀过一次正在吸合的伺服（操作者听到抱闸声才发觉写入其实有效）。

### C. 术语表

| 术语 | 含义 |
|---|---|
