# 埃夫特 EFORT 远程控制台 · PyQt6

RP-2 控制器（Modbus TCP）的远程面板：**关节 ± 步进** + **用户自维护的程序清单** + **测试跑（低速+定时）/ 执行 两档**。
由原 Tkinter 版重写而来，历经多轮现场排故。

## 运行

```
双击 run.bat                或用指定 IP 启动
python main.py --host 192.168.1.12
python main.py --selftest   离屏冒烟（不连机器人）
python main.py --shot       离屏渲染截图到 shots/
```

## ⭐ 一、程序清单 —— 不猜程序号，也不猜程序名（可能是英文）

2026-09-23 需求原话：「**不要猜程序名称也要可能是英文** … 用户可以自己添加文件根据你跑就行了，
**记得保存文件，可以增删什么的**」。

**为什么必须这样**：Modbus 侧只有**数字**（`40104` = 目标程序号），控制器**不会**把程序名吐出来；
而程序文件可能叫 `PICK_A.XPL` 这种英文名 —— 名字只有示教器上有。所以：

```json
{
  "version": 1,
  "jog": 200,
  "list": [
    {"no": 200, "name": "JOGSVC", "note": "点动服务程序"},
    {"no": 410, "name": "PICK_A", "note": "上料"},
    {"no": 411, "name": "WELD_B", "note": ""}
  ]
}
```

- **号** = 唯一会下发给机器人的东西（写 `40104`）；**名字 / 备注** 纯本地，方便你自己认
- **添加 / 改名 / 删除**全部即时**原子落盘**（临时文件 + `os.replace`，断电不留半个文件）
- `jog` = 哪一条是「**点动服务程序**」；0 = 未设置。由界面【设为点动服务】声明
- JSON 损坏 → 改名留档 `.bad`，**绝不静默覆盖**你手写的清单
- 程序号存在下拉 **item data** 里 → 名字里带数字（`PICK_A2`）也不会解析错

> **未指定点动服务程序时**，【一键就绪】会**明确跳过**并提示怎么补 —— 而不是瞎试一个号、
> 白报一次 5005（旧版硬编码 200，而现场**根本没有 200 号**，见下）。

## ⭐ 二、测试跑（低速 + 定时 + 越界） / 执行（直接跑完）

2026-09-21 现场事故复盘：

```
14:52:03 程序 411 已加载（0.61s）
14:52:03 程序熔断已武装：J4 ≤ 10° / 其他 ≤ 5°
14:52:07 熔断触发（其他轴越界 J2 5.63° > 5°）→ 下发 0x1005 停止
```

**熔断本身没错，是阈值用错了地方。** 那 5° 是给**单轴点动**用的保守值（点动时"其他轴"本不该动）。
而**作业程序本来就该让轴大幅运动**（J2 走 30° 很正常）—— 拿点动的尺子量作业程序，必然误杀。

| | **测试跑** | **执行** |
|---|---|---|
| 用途 | 第一次跑新程序、试点位 | 生产 / 正常作业 |
| 速度 | **强制 5%**（忽略界面设定） | 界面设定值 |
| **定时** | **开** —— 跑 N 秒自动停（默认 3s，界面 2/3/5/10/30/60 可选，也可手输） | 不适用 |
| **越界熔断** | **开** —— 任一关节位移 > 上限即停（默认 45°）+ 300s 兜底 | **关** —— 不做位移检测 |
| 保留的保护 | 报警 / 急停 / 通信 / 程序结束 | 报警 / 急停 / 通信 / 程序结束 |
| 跑完 | **不**自动恢复点动（停在现场便于检查） | 按 ☑ 开关自动恢复点动 |
| 下发方式 | 一键 | 一键 |

> 「定时」是 2026-09-23 新增（原话："测试的可以跑 3 秒、2 秒这种可以定时间的去跑"）——
> 有了定时，测试跑就有了**确定的结束条件**，不再依赖"程序自己跑完"或"越界"。
> 一键下发按用户要求（"执行代码的不用，直接运行就行了"）。保护来自：
> **现场安全确认闸门**（必须先勾）+ **Esc 急停** + 报警/急停/通信熔断。

## ⭐ 三、程序扫描 —— 可选，结果自动并入清单

**现场实测的判据**（`tools/probe_load.py` 打出来的时间线）：

| 程序 | `40001.Bit11` 加载位 | 报警 | 耗时 |
|---|---|---|---|
| **411**（存在） | `0 → 1` | 无 | **0.50s** |
| **123 / 3**（不存在） | 从未置位 | **5005** | **0.08s** |
| `40006` 当前程序号 | 加载成功/失败都**不变** | — | 当不了判据 |

⇒ 扫描器用**正反双判据**：报警先到就是"不存在"（快），置位到就是"存在"（慢），谁先到就停。

> ⚠ 历史 bug：旧版把等待窗口设成 **0.5s**，而真实加载要 **0.50~0.61s** —— 卡在临界点上，
> 411 明明存在却被报成"（无）"。现已改为 ≥1.2s 窗口 + 提前退出。
> （另一个坑：当时扫的是 `1~260`，而 411 根本不在区间内。）

**用法**：⑤ 卡 → 设范围（默认 `1~600`）→ 点【扫描】→ 命中项**自动并入程序清单**（不动你已写的名字）。
扫描**只加载、绝不运行**（不碰 Bit1/Bit2，机器人不动），结束自动清报警、还原 `40104`、恢复点动服务。
扫描在主循环里**逐号推进**（状态机），所以扫描期间 UI、快照、急停**全程可用**。

### 📋 现场扫描结论（2026-09-21 / 09-23 两次一致）

| 区间 | 存在的程序号 |
|---|---|
| 1~300 | **无** |
| 301~600 | ✅ **410（0.51s）、411（0.55s）** |
| 601~999 | **无** |

> **重要**：控制器上**没有 200 号程序** —— 而旧版硬编码把 200 当"点动服务程序"，
> 这就是点动反复报 5005 的根因（现已改成"由用户清单指定，未指定就明确跳过"）。
> **点动功能要能用，先在示教器上把点动服务程序建出来**（步骤见 ③ 卡的【程序模板】），
> 然后把它的号 [添加] 进清单并点 [设为点动服务]。

## ⭐ 四、关节 ± 步进（= 示教器那 12 个键的等价物）

原来每轴 8 个按钮（6×8 = 48 个）+ 位移色条，现在按需求**全部删掉**，改成：

```
④ 关节        当前在动：J4          步长 [1° ▼]   其他轴限 [1.5°]
  J1   +73.340°   [ − ]  [ + ]   ● 在动   Δ+0.00
  J2   −49.490°   [ − ]  [ + ]            Δ+0.00
  … 共 6 行
```

- **6 个坐标**实时显示；哪个轴在动 → 坐标变蓝 + 显示「**● 在动**」+ 顶部汇总「当前在动：J4」
- **12 个按钮**（6 轴 × −/+）= 示教器 J1~J6 的 ± 控制键；步长 0.1 / 0.5 / 1 / 5 / 10° 可换
- 「Δ」= 自【设基线】以来的位移

**通道没变**（已在真机验证过）：写 `40139~44`（绝对目标角 ×100）→ 置 `40135.Bit0` 触发
→ 常驻程序 `WAIT` 放行 → `MJOINT` → 回执 `40035.Bit0` → 撤触发、基线归零。

> ### 关于"示教器原生那 12 个 J± 命令" —— 已按"获取不到就不获取"结案
>
> | 路子 | 结果 |
> |---|---|
> | 抓示教器↔控制器报文 | ❌ 示教器在 **ETH3A**、PC 在 **ETH3B**，是控制器内部链路，PC 侧抓不到 |
> | Modbus 里找关节指令 | ❌ 已穷举：`40101` 指令位只到 Bit13，**没有任何关节级/点动指令** |
> | 8000 端口（疑似墨斗 IDE 在线调试私有协议） | ⚠️ 存在但**无任何文档**；对运动控制器盲试有真实风险，不做 |
>
> ⇒ 交付的是**功能等价物**：12 个 ± 按钮 + 控制器上的常驻程序，且已在真机验证可行。

## 安全边界（绝不妥协的部分）

| 场景 | 行为 |
|---|---|
| **急停（Esc）** | 撤点动触发位 + `0x1005`，且 **绝不自动恢复任何东西**；中止进行中的扫描 |
| **熔断触发**（报警 / 急停 / 测试跑越界 / 超时） | 立即 `0x1005`；**不自动恢复点动**，提示人工确认后重新就绪 |
| **测试跑到设定时长** | 正常结束：立即 `0x1005` 并说明"按计划结束"（不是故障）；同样不自动恢复点动 |
| **熔断武装期间** | 重入保护：拒绝新的点动/运行；UI 侧锁住 ± 按钮 |
| **手动模式（T1/T2）** | 外部控制被禁用 → 不拉起服务、不假装成功；界面弹告警 |
| **未指定点动服务程序** | 就绪时明确跳过、点动时明确拒绝并指路 —— **绝不瞎试程序号**（避免白报 5005） |
| **伺服未上电 / 有报警** | 前置校验直接拒绝动作 |
| **通信中断** | 自动重连（1→2→4→8→10s 退避），恢复后提示需重新就绪（不静默） |
| **执行档** | 越界检测关闭，但报警 / 急停 / 通信 / 程序结束**四道保护全在** |

## 保留的原设计（已验证有效，未改）

- **一键就绪**：连接 → 有报警就清 → 伺服上电（含 0.55s 吸合延迟处理）→ 拉起点动服务
- **加载失败善后**：自动清 5005、`40104` 还原为控制器当前程序号、锁存该号不再重试
- **对照诊断**：加载失败时拿"控制器当前程序号"再试一次，区分"机制坏了"与"该程序不在"
- **熔断补发**：熔断后 0.5s 异步补发 `0x1001`（仅保持伺服）

## 使用前提（只需做一次）

1. 控制器上建好**点动服务程序** —— 官方录入步骤见 ③ 卡的【程序模板】，`docs/` 里有更细的说明。
2. ⑤ 卡【添加】它的程序号（+ 你自己认得出的名字），选中后点【设为点动服务】。
   （不知道号就先点【扫描】，命中项会自动进清单。）
3. 点【一键就绪】拉起服务，之后 **± 按钮** 就能动关节。

**安全提醒**：真机会动，动手前确认作业区没人；软件熔断是第二道防线，不是唯一防线；手要放在急停上。
